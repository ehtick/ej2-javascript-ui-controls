## 💡 Core Principles for Success

### 1. **Architecture First**
Always understand the architecture before implementing changes. Never make changes in isolation.

### 2. **Requirements Clarity**
Thoroughly understand user requirements before coding. Ask clarifying questions and document assumptions.

### 3. **LLM as Co-Pilot, Not Replacement**
Use LLMs to accelerate understanding and generate drafts, but always review and validate their output against architecture.

### 4. **Code Quality Over Speed**
- Follow established naming conventions
- Write comprehensive XML comments
- Ensure backward compatibility
- Add regression tests for any changes

### 5. **Modular Thinking**
- Each feature is independent yet interconnected
- Understand the impact chain of your changes
- Test feature combinations, not just individual features

### 6. **Documentation is Part of Code**
- Keep architecture docs synchronized with implementation
- Document design decisions, not just what the code does
- Maintain clear change logs

## 🔄 Development Workflow

```
User Requirement → Requirements Analysis → Architecture Review
        ↓              ↓                        ↓
   LLM Exploration → Code Generation → Quality Review
        ↓
   Implementation → Testing → Documentation
        ↓
   Code Review → Regression Testing → Release
```

## ⚠️ Critical Rules - Never Violate These

1. **API Compatibility**: Never introduce breaking changes to public APIs
2. **Regression Testing**: Every behavior change requires regression tests
3. **Performance**: Changes must not impact grid performance (benchmark before/after)
4. **Accessibility**: All changes must maintain WAI-ARIA compliance
5. **Memory**: Avoid memory leaks (particularly in infinite scroll and virtualization)
