# SpecCoverageReportGenerator

Converts method JSON (from a TS-to-JSON tool) into a coverage report.

## Before you run
- Paste `methods.json` into `Files/Inputs` (generated by the TS-to-JSON tool).
- Paste spec files for the module into `Files/Specs` (markdown files).
- `Files/Outputs` will contain `methods.txt` and `coverage_report.md` after a run.

## Folder structure
- `Files/Inputs` — input `.json` files (required).
- `Files/Specs` — specification files to search (required).
- `Files/Outputs` — generated `methods.txt` and `coverage_report.md` (created if missing).

## Run
From the project folder, follow these steps:

1. **Restore dependencies**
   ```bash
   dotnet restore
   ```

2. **Build the project**
   ```bash
   dotnet build
   ```

3. **Run the application**
   ```bash
   dotnet run
   ```

4. **Follow the prompts**
   - Choose whether to write methods to file (Y/N)
   - Choose whether to generate coverage report (Y/N)
   - View results in `Files/Outputs` folder


## Notes
- Make sure `Files/Inputs` contains matching `.json` method data for the spec files you placed in `Files/Specs`.

## Example prompts

- To generate spec

```
Generate spec for #file:ribbon module inside #openspec\specs\ribbon folder using #file:SKILL.md in deep mode. Must cover all the methods for this module. Must read all the files inside nested folders also and generate spec
- *Run spec-gen on this codebase. Generate spec for #file:modulefolder  module using #file:openspec-skill.md  in deep mode. Must cover all the methods for this module in #file:methods.txt*
```

- For update uncovered methods

```
Still found these methods #file:uncoveredmethods.txt are not covered and improve the spec by covering these methods. Don't add separate section, must cover in any one topic such as Requirements, or Data flows or where to start debugging.

Maintain same signature in spec files, if wrong, replace with proper signature
```
