## 📖 Specification Format

Each specification follows OpenSpec conventions:

### Structure
```markdown
# {Domain} - {FeatureName} Specification

> Generated by spec-gen on {date}
> Source files: {list of analyzed files}

## Purpose
{2-3 sentences describing the feature}

## Requirements

### Requirement: {RequirementName}
{The system SHALL/MUST/SHOULD do X...}

#### Scenario: {ScenarioName}
- **GIVEN** {precondition}
- **WHEN** {action}
- **THEN** {expected outcome}

## Technical Notes
- **Implementation**: {file paths}
- **Component**: {domain name}
- **Feature**: {feature name}
- **Dependencies**: {related features}
```

### Key Conventions
- ✅ RFC 2119 keywords (SHALL, MUST, SHOULD, MAY) for requirements
- ✅ Given/When/Then format for scenarios
- ✅ Exactly 4 hashtags (`####`) for scenarios
- ✅ Hyphen naming: `{domain}-{featureName}`
- ✅ Source file references for traceability
- ✅ Technical notes with implementation details
